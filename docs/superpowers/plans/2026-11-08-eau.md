# Suivi de l'eau — plan d'implémentation

> **Pour les agents :** sous-skill requis : superpowers:executing-plans. L'utilisateur a demandé « code » : exécution dans la session. Étapes à cocher (`- [ ]`).

**Objectif :** carte « Eau » dans le journal (+ 250 ml, + 500 ml, « Autre… », « Annuler le dernier »), objectif automatique d'après le poids ou manuel, tuile « Eau moyenne » dans Tendances.

**Architecture :**
- Une table `water_logs` (une ligne par prise d'eau) protégée par RLS, et une colonne `water_goal_ml` dans les préférences.
- Des calculs purs dans `src/utils/water.ts`.
- Un service et un hook (`useWaterDay`) pour la carte, une section Paramètres, et une tuile ajoutée à `InsightsPanel`.

**Stack :** Supabase (Postgres 17, RLS), React 18 + TS, Vitest + Testing Library, tests SQL, Playwright + axe.

**Spec :** `docs/superpowers/specs/2026-11-08-eau-design.md`

## Contraintes globales

- Prise d'eau : 1 à 3 000 ml (entier).
- Objectif manuel : 500 à 6 000 ml, `NULL` = automatique.
- Objectif automatique : `weightKg × 30` ml, arrondi aux 100 ml, borné entre 1 500 et 4 000 ; 2 000 sans poids.
- Litres à la française, 2 décimales au plus (« 0,5 L », « 1,25 L », « 2,4 L »).
- Textes en français et au vouvoiement ; couleur de donnée `info` (barre `info-500`, goutte `info-600`), `success-500` quand l'objectif est atteint.

## Points d'attention en revue

1. Double tap rapide sur « + 250 ml » : un seul ajout tant que l'envoi est en cours, boutons désactivés (tâche 3, test de la carte).
2. Changement de date du journal pendant le chargement : la carte affiche le total du jour choisi, pas l'ancien (tâche 3, test du hook avec deux dates).
3. Objectif personnalisé saisi avec une virgule (« 2,5 ») : accepté, 2 500 ml (tâche 4).
4. Poids absent du profil : objectif automatique de 2 L, sans plantage (tâche 2).
5. Suppression du compte et export : `water_logs` inclus (tâche 1).

### Tâche 2 : calculs et préférences

**Produit :**

- Calculs :
  - `autoWaterGoal(weightKg?: number | null): number`
  - `waterGoal(goalMl: number | null, weightKg?: number | null): number`
  - `waterTotal(logs: readonly Pick<WaterLog, 'amount_ml'>[]): number`

  - `weeklyWaterSummary(logs: readonly WaterLog[], goalMl: number, today: string): { averageMl: number | null; loggedDays: number; daysAtGoal: number }`
- Format et validation :
  - `formatLiters(ml: number): string`
  - `validateWaterAmount(ml: number): string | null`
  - `parseLiters(text: string): number` (« 2,5 » → 2 500, `NaN` si invalide)
  - `validateWaterGoal(goalMl: number | null): string | null`
- Préférences : `UserPreferences.waterGoalMl: number | null` (défaut `null`) ; `preferencesFromRow` et `preferencesToRow` lisent et écrivent `water_goal_ml` ; `validatePreferences` ajoute l'erreur de `validateWaterGoal`.

### Tâche 3 : carte « Eau » dans le journal

**Fichiers :** créer `src/services/water.ts` (+ test), `src/components/Water/useWaterDay.ts`, `src/components/Water/WaterCard.tsx` (+ test) ; modifier `src/components/Dashboard/Dashboard.tsx`.

**Interfaces :**
- Service :
  - `fetchWaterLogs(userId: string, from: string, to: string): Promise<WaterLog[]>` (dates incluses, tri par `created_at`) ;
