# Pied de page et page « À propos » — plan d'implémentation

> **Pour les agents :** sous-skill requis : superpowers:executing-plans. L'utilisateur a demandé « code » : exécution dans la session. Étapes à cocher (`- [ ]`).

**Objectif :** pied de page avec version et liens, et page « À propos » (CalTrack, Santé, Vos données, Sources) accessible connecté ou non.

**Architecture :**
- Version lue depuis `package.json` (constante Vite) ; nouvelle vue `'about'` dans la navigation, avec une section cible.
- Deux composants (`AppFooter`, `AboutPage`) branchés dans `App.tsx`, connecté et sur l'écran de connexion.

**Stack :** React 18 + TS, Vite 5, Vitest + Testing Library, Playwright + axe.

**Spec :** `docs/superpowers/specs/2026-11-09-a-propos-design.md`

## Contraintes globales

- `package.json` en `1.0.0` ; aucune version écrite en dur ailleurs.
- Textes de la spec, en français et au vouvoiement ; liens externes `https://ciqual.anses.fr` et `https://world.openfoodfacts.org` en nouvel onglet (`rel="noopener noreferrer"`).
- Composants et classes du design system (`page-title`, `card-title`, `panel`, `Button`).

## Points d'attention en revue

1. Ouvrir « Sources » alors que la page « À propos » est déjà affichée : la page défile quand même vers la section (dépendance sur la section, pas seulement au montage) — test `AboutPage` avec changement de section.
2. Écran de connexion → « À propos » → « Retour à la connexion » : on retrouve le formulaire (mode connexion ou inscription conservé) — test `App`.
3. Les boutons du compte n'apparaissent pas sans connexion (pas de page Compte accessible) — test `AboutPage`.
4. Pied de page masqué derrière la barre d'onglets mobile : rendu dans `main` qui a déjà `pb-28` — vérifié sur la capture mobile.
5. `scrollIntoView` absent de jsdom : appel protégé (`?.`) — tests verts sans le simuler partout.

### Tâche 1 : version et navigation

**Fichiers :** `package.json`, `vite.config.ts`, `src/vite-env.d.ts`, créer `src/utils/appInfo.ts` ; modifier `src/utils/navigation.ts` (+ test `navigation.test.ts`).

**Produit :**
- `APP_VERSION: string` (depuis `__APP_VERSION__`, déclaré `declare const __APP_VERSION__: string`).
- Navigation :
  - `type AboutSection = 'app' | 'health' | 'data' | 'sources'` et `ABOUT_SECTIONS` ;
  - `AppView` gagne `'about'` ;
  - `NavigateEventDetail { view; section?: AboutSection }` ;
  - `navigateTo(view, section?)` ;
  - `isAboutSection(value)`.

- [ ] Tests :
  - `isAppView('about')` → `true` ;
  - `navigateTo('about', 'sources')` émet un événement dont `detail` vaut `{ view: 'about', section: 'sources' }` ;
  - `isAboutSection('x')` → `false`.
- [ ] Échec, implémentation (`define` dans `vite.config.ts` à partir de `package.json` lu par `readFileSync` et `JSON.parse` ; `test.define` identique pour Vitest), tests verts. Commit.

### Tâche 2 : composants `AppFooter` et `AboutPage`

**Fichiers :** créer `src/components/Layout/AppFooter.tsx` et `src/components/About/AboutPage.tsx`, avec un test commun `src/components/About/About.test.tsx`.

**Interfaces :**
- `AppFooter({ onOpen(section: AboutSection), showAttribution?: boolean })` ;
- `AboutPage({ section?: AboutSection, signedIn: boolean, onBack?: () => void, onOpenAccount?: () => void })`.

- [ ] Tests :
  - pied de page : « CalTrack v1.0.0 » ; « À propos » → `onOpen('app')`, « Vos données » → `onOpen('data')`, « Sources » → `onOpen('sources')` ; attribution affichée seulement avec `showAttribution` ;
  - page :
    - titres CalTrack, Santé, Vos données, Sources ;
    - « Version 1.0.0 » ;
    - liens Ciqual (Licence Ouverte 2.0) et Open Food Facts (ODbL), avec `target="_blank"` ;
    - « Paris » dans Vos données ;
    - boutons « Télécharger mes données » et « Supprimer mon compte » appelant `onOpenAccount` si `signedIn`, absents sinon ;
    - « Retour à la connexion » appelle `onBack` ;
    - `scrollIntoView` appelé sur la section `sources` au rendu, puis sur `data` après changement de `section`.
- [ ] Échec, implémentation, tests verts, lint. Commit.
